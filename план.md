## 1. Контекст и решение
- Проект: Timer_sound, Kotlin + Compose + Foreground Service. Группы (до 30), в группе будильники (до 100). У каждого будильника свой `fileUri` (SAF), `intervalMs`, `SceneMode` (REPEAT/ONCE_TIME/INTERVAL/RANDOM).
- Расхождение с исходной постановкой («один файл на приложение») устранено: источник «Папка» делается **на уровне будильника** (`AlarmConfig`), а не глобальным переключателем. Один будильник = либо один файл, либо папка. Остальные будильники группы не трогаем.
- Фон не дублируем: используется существующий `TimerSoundService` (тик-цикл + `setAlarmClock` + wakelock + `AudioEngine` на `Ringtone`). Математику `TimerSession` не меняем.

## 2. Что реализуем (scope зафиксирован)
- Источник на будильник: `Один файл` (как сейчас) / `Папка со звуками` (новое).
- Режимы папки — только два, на этом останавливаемся:
  - Последовательно: 1-й, 2-й, … по списку, после последнего — сначала (в рамках настроек N раз / лимитов группы).
  - Случайно без немедленного повтора: каждый тик случайный файл, кроме только что игравшего (если файлов > 1).
- UI: под громкостью к трём кнопкам («Выбрать», «Встроенный бип», «Удалить») добавляется четвёртая — «Выбрать папку». Других перестроек UI нет.
- Ключевой сценарий из обсуждения: в одном будильнике выбрана папка, в соседнем — одиночный звук; они не конфликтуют, не глушат друг друга, не плодят таймеры.
- Плавающая громкость (отдельная функция, на уровне будильника): рядом с фиксированной громкостью 0–100% добавляется режим диапазона, например 50–80%: каждое срабатывание играет на случайной громкости внутри диапазона. 100% = стабильно 100%, без изменений старого поведения.

## 3. Изменения по файлам
1. `model/TimerConfig.kt` (`AlarmConfig`):
   - `sourceType: FILE | FOLDER` (default FILE), `folderUri: String = ""`, `folderName: String? = null`,
   - `folderFiles: List<FolderEntry(uri: String, name: String)>` — кэш сканирования (SAF Uri, не абсолютные пути),
   - `folderPlayMode: RANDOM_NOREPEAT | SEQUENTIAL`, `lastFolderIndex: Int = -1`,
   - `hasFile`/`playableAlarms()`/`scheduleValid` — для FOLDER играбельность = `folderFiles.isNotEmpty()`.
2. `data/AlarmJson.kt`: новые поля в `AlarmDto` + `toDto/toAlarmConfig`; `ignoreUnknownKeys` уже есть → старые конфиги мигрируют в FILE без потерь.
3. `TimerViewModel.kt`: `onFolderPicked(groupId, alarmId, treeUri)` — `takePersistableUriPermission`, `queryDisplayName`, сканирование; `setSourceType`, `setFolderPlayMode`, `clearFolder`; `releasePersistableUriPermission` для папки только если URI не используется другими будильниками (аналогично файлам); `fileDisplayName` — ветка папки («Папка: <имя> (N)»).
4. Новый `audio/FolderScanner.kt` (или `data/`): перечисление детей `DocumentFile.fromTreeUri`, фильтр `audio/*` + расширения mp3/wav/ogg/m4a/aac/flac/mid/opus; только первый уровень; сортировка по имени для стабильности последовательного режима.
5. Новый `audio/FolderSoundPicker.kt`: чистая функция `nextIndex(size, mode, lastIndex, random)` — без повтора при size > 1; unit-тестируется без Android.
6. `service/TimerSoundService.kt` (`handleTickGroup`): перед `AudioEngine.play` — если источник FOLDER, резолв `pickedUri = folderFiles[pickerIndex]`, вызов `play` с `AlarmConfig.copy(fileUri = pickedUri)`, обновление `lastFolderIndex` через ViewModel/репозиторий (без перезапуска сессии, без второго таймера). Ошибка одного файла → пропуск тика + счётчик последовательных ошибок (защита от бесконечного цикла на битом файле).
7. `ui/AlarmCard.kt` (expanded): сегмент «Один файл / Папка», кнопка «Выбрать папку», строка «Папка: <имя> (N файлов)», при N>0 — первые ~5 имён; режимы папки — два чипа; сводка `alarmSummary` дополняется.
8. `ui/GroupDetail.kt`: `OpenDocumentTree()`-лаунчер рядом с существующим `OpenDocument()` для одиночных файлов; сообщение о пустой папке / потере доступа («доступ потерян — выберите папку снова»).
9. `PreferencesRepository` — без новых таблиц, тот же DataStore JSON.
10. Плавающая громкость (`AlarmConfig`): `volumeMode: FIXED | RANDOM_RANGE` (default FIXED), `volumeMin: Int`, `volumeMax: Int` (0–100, инвариант `0 <= min <= max <= 100`); при FIXED используется существующий `volumePercent`, при RANDOM_RANGE каждое срабатывание — `random(min, max)`. Резолв громкости — там же, где резолв URI папки в `handleTickGroup`, перед `AudioEngine.play` (один `Random` на процесс/сессию, не новый на тик). Preview — играть на среднем диапазона или на текущем превью-значении, без рандома на каждый ползунок. UI: переключатель «Фикс / Диапазон» + два слайдера/поля min-max + валидация (min<=max, кламп 0–100). Сериализация — те же `AlarmDto`.

## 4. Неконфликтность многих будильников (обязательно)
- Ключ звука остаётся `(groupId, alarmId)` — папка и одиночный файл в соседних будильниках не делят плеер; `stopChannel/stopGroup/releaseAll` без изменений.
- Один тик = один `play` на будильник; семантика интервалов (от срабатывания, catch-up max 3 для REPEAT, лимит `MAX_CONCURRENT_RINGS=10`) сохраняется.
- `overlappingAlarms` (предупреждение об одинаковом `fileUri`) дополнить веткой папок: пересечение по фактическим URI из кэша, иначе папка vs одиночный с тем же файлом молча наложится.
- Пауза/стоп/рестарт группы затрагивают все будильники одинаково; повторный старт не создаёт второй тик-цикл (существующая очередь команд `limitedParallelism(1)`).

## 5. Ошибки и edge cases
- Пустая папка / нет аудио → FOLDER не играбелен, старт блокируется как при пустом файле + текст причины.
- Доступ отозван / папка удалена → при старте и при рестарте приложения проверка `persistedUriPermissions`; статус «доступ потерян», сессия остальных будильников продолжается, краша нет.
- Файл удалён/перемещён/содержимое изменилось → пересканирование при старте группы; отсутствующий URI пропускается.
- Битый/невоспроизводимый файл → пропуск + лог, без ANR; подряд N ошибок — пропускаем будильник до следующего тика, не зацикливаемся.
- Scoped Storage: только SAF Uri + persistable-права, никаких абсолютных путей и `MANAGE_EXTERNAL_STORAGE`.

## 6. Тесты (обязательны, по требованию)
- Unit (JVM/Robolectric): picker — нет повтора при size>1, равномерность/границы; sequential — порядок + wrap; громкость — random всегда внутри [min,max], границы min==max и 0–100, инвариант min<=max, FIXED не трогает volumePercent; миграция v3→v4 (FILE default, FOLDER round-trip, volumeMode default FIXED); `playableAlarms` для папок; сессия — резолв не сдвигает фазу интервалов.
- Ручные на устройстве (Huawei, фон): одиночный файл как раньше; папка MP3 по интервалу; рандом без повтора (лог последних индексов); sequential по порядку; фиксированная громкость 100% — стабильно; диапазон 50–80% — на слух/по логу громкость разная при каждом срабатывании и не выходит за границы; min==max ведёт себя как фикс; папка + одиночный в соседних будильниках — оба звучат, без наложений сверх существующего лимита; сворачивание + выключенный экран; перезапуск приложения — папка и права на месте; потеря прав/пустая папка — понятные сообщения; многократный старт/стоп — один тик-цикл; переключение FILE↔FOLDER без дублей.
- Сборка: `compileDebugKotlin`, `testDebugUnitTest`, `assembleDebug`; исправить все ошибки компиляции от изменений.

## 7. Критерий готовности
Пользователь на будильник выбирает либо файл, либо папку (4-я кнопка под громкостью); папка играет по существующим интервалам/раунд-режимам в фоне так же стабильно, как одиночные файлы; громкость — либо фикс (как раньше), либо случайная в заданном диапазоне при каждом срабатывании; соседние будильники не конфликтуют; тесты из §6 пройдены.
